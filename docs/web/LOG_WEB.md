## Aturan yang dipelajari (berlaku untuk semua PR Devin berikutnya)

- Klaim "selesai" dari Devin hanya diterima bersama output git mentah dan hasil menjalankan endpoint terhadap site nyata. Tiga putaran berturut-turut ringkasan tidak cocok dengan repo.
- Perbaikan `.py` kecil boleh ditulis Claude sebagai skrip patch untuk dijalankan Efendy, selalu dengan backup dan `py_compile`. Pastikan nama host (`erpnext`, bukan `cmlerp`) sebelum menjalankan.
- Review dari kode saja tidak menangkap CSRF dan layout tabel; setiap tahap harus diuji dengan satu POST nyata dan dilihat di browser.
- Aturan CSS yang ditulis untuk satu tabel (`nth-child`) jangan berlaku global; beri kelas khusus per jenis tabel.
- Tes yang hanya berisi `pass` terlihat "lulus" padahal tidak menguji apa pun; tolak di review. Tanpa site uji, pengganti tes otomatis adalah skrip uji `bench console` yang dijalankan Efendy.
- `frappe.db.rollback()` di skrip uji tidak menjamin data uji hilang (alur bisnis bisa commit sendiri). Selalu cek sisa data uji di akhir skrip dan sediakan skrip pembersih; beri judul khusus pada data uji (mis. awalan "ZZ UJI") agar mudah dibersihkan.
- Sebelum menyimpulkan nasib sebuah PR, cek dulu apakah sudah ter-merge ke `main` (lewat `git pull` / diff stat), jangan berasumsi dari status branch.
- Untuk Devin: selalu `git --no-pager`, `git commit -m` (tanpa editor), tanpa rebase interaktif, agar tidak macet di pager/Vim dan menghabiskan token.
- Menu navigasi bersama ada di `ui.js` (`renderNav`); halaman baru perlu ditambahkan ke daftar `links` di sana.
